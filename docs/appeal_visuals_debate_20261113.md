## 3. 제작 방식 비교 (요약)
| 방식 | 품질 상한 | 안정성 |
|---|---|---|
| 기본 도형 개선 | 블롭형은 상한에 가깝게, 동물형은 이음매·막대 다리 한계 | 업로드 없음, 장애 시 클라이언트 외형만 영향, Spec으로 고정 쉬움 |
| Python 절차 메시 | 수학적 형태(물방울·꽃잎) | 자체 기하 코드의 구멍·법선·winding 결함 위험, 결정적 생성이라 unittest 고정은 쉬움 |
| headless Blender | 가장 넓음(곡면·접합·리그·렌더) | 검증된 modifier로 기하 결함 위험 낮음, 버전 의존(버전 고정 필요), 설치 승인 필요 |
| 메시 몸체 + 도형 얼굴 | 메시 도입 시 구조 | 로딩·심사·권한 실패 시 도형 폴백, 얼굴 앵커 좌표 계약 필요 |

Roblox 제약(공식 문서, Codex·Claude 확인): 메시당 20,000 triangles, 닫힌 형상·두께, 정점당 최대 4본 영향, FBX 애니메이션 트랙별 내보내기, Importer는 OBJ·FBX·glTF, 업로드 자산은 게시 게임 사용 전 심사.

## 사용자 결정 (2026-11-13)
- **MVP1 전 범위:** 위 I2의 세 가지(외형 수정·포획/배치 기쁨 반응·정원 최소 연출)를 S7·S8 완료 기준에 넣는다. 탭 반응·주인 바라보기·표정 controller는 동결 예외 후보로 남긴다.
- **미리보기:** 반짝이 얼굴·재질 A/B(한 번에 한 변수 + 종합안)와 사슴 다리 비교안을 Studio 없이 미리보기로 먼저 만들어 사용자가 고른다.
- **평가:** 10~20대 블라인드 평가는 불가 → 사용자가 직접 보고 판단한다(소수 선호도 통계적 근거가 아님을 전제).
- **메시 시험:** 나중에 집(Windows)에서 사용자가 진행한다. Blender 설치·11/11 "그래픽 = 임시 도형" 결정 변경은 그때 다시 정한다.
