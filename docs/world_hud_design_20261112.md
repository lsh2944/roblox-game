## 1. 월드 배치 (meadow, 단위 studs)

```
                 [숲 관문 — 잠김 표지(forest, MVP1 범위 밖)]
                               │
        ┌──────────── 이슬 초원(필드) ─────────────┐
        │  이슬 연못(meadow_dew)      꽃밭(meadow_bloom) │
        │        야생 출현 구역(플레이어별 1마리)      │
        └──────────────────┬───────────────────────┘
                           │ 길
  부지1  부지2  부지3  ── 광장(스폰·게시판) ──  부지4 … 부지N
```

| 요소 | 제안 | 근거·메모 |
|---|---|---|
| 광장(허브) | 원점. 일일 의뢰 게시판, 안내 표지 | 첫 접속 플레이어의 기준점 |
| 플레이어 부지 | 광장 둘레에 반원/원형으로 N개. 부지 1칸 = 약 64×64 | PlotService가 접속 순서대로 배정하고 퇴장 시 반납한다. 좌표 표는 `Config`(서버) |
| 부지 안 | 집(임시 도형) 1채, 시설 받침대 2개(dew_spring, bloom_garden) + **예약 자리 1개**(crystal_forge, forest), **전시대 3칸 자리**(MVP 후속), 이름표 | 예약 자리는 나중에 좌표를 다시 짜지 않으려고 미리 둔다 |
| 채집 노드 | 필드 안에 공유 노드 2개(연못, 꽃밭). 여러 플레이어가 동시에 채집해도 고갈 없음 | GatherService는 노드 id + 거리만 본다. 노드 id = `fields.json`의 `gather_nodes[].id` |
| 노드 크기 | 반지름 6~8 정도의 시각 영역. 판정은 `GATHER_RADIUS=12` | 반경은 Studio에서 걸어 보며 조정(임시값) |
| 야생 출현 구역 | 필드 중앙 원형 구역. 플레이어마다 포획 대상 최대 1마리 + 모두에게 보이는 장식 정령 무리(W2 하이브리드) | WildSpawnService 계약 그대로. 출현 위치는 서버 표 |
| 숲 관문 | 필드 뒤쪽에 잠긴 문 + "Coming soon" 표지 | 필드 해금은 범위 밖이지만 방향을 미리 정해 둔다 |

## 2. 상호작용 방식

| 대상 | 제안 | 안정성 메모 |
|---|---|---|
| 채집 노드·야생 정령 | 클라이언트가 **ProximityPrompt**를 표시하고, Triggered 시 기존 RF(`GatherStart`, `CaptureEngage`)를 호출한다 | 서버 입구가 Remote 하나뿐이라 검증·레이트 제한 경로가 둘로 갈라지지 않는다. 서버의 Prompt.Triggered로 바로 처리하면 Validate·RateLimiter를 우회하는 두 번째 입구가 생긴다 |
| 시설 관리 | HUD의 "Home" 버튼으로 어디서든 패널을 연다. 부지의 받침대는 보이기만 하고, 다가가면 같은 패널을 여는 Prompt를 붙인다 | 방치형 편의. 두 방식 모두 같은 RF(`AssignSlot`/`MoveSlot`/`UpgradeFacility`)를 쓴다 |
| 이동 | 접속 시 **자기 부지**에서 시작한다. HUD에 "Meadow"·"Home" 이동 버튼(서버가 위치를 정해 텔레포트) | 서버가 목적지를 정하므로 좌표 조작이 없다. 거리 검사는 기존처럼 최선의 노력 수준 |

## 3. HUD (모바일 가로 우선, 코드로 만드는 ScreenGui)

Roblox는 모바일 비중이 높다고 알려져 있어(추측, 수치 미확인) 터치 크기와 safe area를 우선한다. 문구는 영어 기본(`Text.luau`).

| 위치 | 내용 |
|---|---|
| 왼쪽 위 | 지갑: Dew · Bloom · Wick · Meadow Materials(hunt_meadow). 숫자는 축약 표기(1.2K) |
| 오른쪽 위 | Daily 상태(받음/다음 초기화까지 UTC 0시 카운트다운). 밤 시계 자리 예약(밤은 MVP1 범위 밖) |
| 왼쪽 세로 메뉴 | Spirits(보관함·동행) · Home(시설) · Craft · Collection(도감) |
| 아래 가운데 | 상태 칩: "Gathering Dew +N/s"·범위 이탈 경고, 조우 중에는 숨김 |
| 위 가운데(조우 카드) | 종 이름·등급(등롱 사용 시 공개), 약화 진행 바, 시도 n회째, **성공률 %·다음 도망 확률 % 상시 표시**(I1 결정), 남은 심지, 결과 배너(성공/도망/심지 부족) |
| 토스트 | `Notify` RE(보관함 가득 등). 화면 위쪽에서 3초 |
| 피해야 할 곳 | 오른쪽 아래(모바일 점프 버튼), 왼쪽 아래(이동 조이스틱), 위쪽 가운데의 Roblox 기본 메뉴 영역 |

### 패널
1. **Spirits**: 보관함 그리드(100칸, 정렬: 등급/최근), 동행 3칸, 상세(채집·전투 축별 개체값, 우수 표시, 상태: 동행/배치/대기). 동행·배치는 배타(Q3 결정)라서 상태 배지로 보여 준다.
2. **Home**: 시설 카드(이슬 샘, 꽃빛 정원). 칸 3~5, 배치된 정령, 시간당 생산, 강화 버튼(비용, Lv4·7·10의 사냥 재료 관문 표시). 배치는 "정령 선택 → 칸 탭"으로 하고, 찬 칸이면 자리를 바꾼다(`MoveSlot` 계약).
3. **Craft**: 심지 레시피(hunt_meadow 5 → 심지 25), 횟수 1..100.
4. **Collection**: meadow 5종. 미발견은 실루엣, 발견하면 최고 개체값 카드.

## 4. 사용자 결정이 필요했던 항목 (권장안)
결과는 문서 끝 "사용자 결정"에 있다. W2는 권장안(주인만 봄)이 아니라 하이브리드로 정해졌다.


| # | 질문 | 권장 | 이유(안정성 기준) |
|---|---|---|---|
| W1 | 서버당 최대 인원(= 부지 수) | **8** | 부지 좌표 표가 고정 크기라 테스트로 전부 확인할 수 있다. 인원이 많을수록 월드가 커지고 스냅샷 복제·DataStore 요청(`60 + 인원×40`/분)이 늘어난다. 방치형은 다인 상호작용이 적다 |
| W2 | 야생 정령을 누가 보나 | **주인만 본다**(클라이언트 표시) | 서버 계약이 이미 "본인 소유만 engage"다. 남에게도 보이면 "보이는데 못 잡는" 혼란과 신고성 문의가 생긴다. 장식용 정령은 따로 둘 수 있다 |
| W3 | 채집·포획 입력 | **ProximityPrompt → 기존 RF** | 2절 표 참고. 서버 입구가 하나로 유지된다 |
| W4 | 접속 시작 위치 | **자기 부지** | 방치 생산을 먼저 확인하는 흐름. 텔레포트 목적지는 서버가 정한다 |
| W5 | 시설 관리 위치 | **HUD 패널(어디서나) + 받침대 Prompt** | 같은 RF를 쓰므로 경로가 늘지 않는다 |

## 5. 범위 밖(자리만 예약)
전시대 3칸, 방문 공개/비공개 전환, 숲 관문 해금, 밤 시계, 결제 UI. 좌표·HUD 자리만 비워 두고 구현은 각 단계에서 한다.

## 사용자 결정 (2026-11-12)
- W1 서버당 최대 8명 = 부지 8개.
- W2 **하이브리드**(사용자 의도: 포켓몬·팰월드처럼 정령이 보이는 세계).
  - 장식용 야생 정령 무리: meadow 종 외형으로 필드를 돌아다니고 모두에게 보인다. 포획할 수 없다. 클라이언트에서만 그리고, 서버 시각과 공유 시드로 모든 클라이언트가 같은 경로를 계산한다(통신 없음). 저장·경제·서버 판정과 무관하다.
  - 포획 대상: 플레이어별 1마리, 종은 등롱을 쓸 때 공개(Q2 유지). 분명한 표식과 `Use Lantern` Prompt로 장식 정령과 구분한다. 다른 플레이어에게 표식을 보일지는 S7에서 정한다.
  - 동행 3마리가 플레이어를 따라다니고 모두에게 보인다(계획서 4.2의 "궤도 모션"). 외형 스킨(BM)을 보여 주는 자리가 된다.
  - 확인 필요(Studio): 장식 정령과 포획 대상을 헷갈리지 않는지, 정령 수에 따른 모바일 프레임.
  - 검토했지만 채택하지 않은 안: 누구나 잡는 공유 야생 정령(1인당 조우 속도 계약 파괴, 뺏기·동시 등롱 경합), 출현 때 종 공개(Q2 변경, 재접속 재추첨을 막을 저장과 sim 재조정 필요).
  - 출시 후 후보: 공유 "이벤트 정령". 서버 전체에 가끔 나타나고, 모인 플레이어가 각자 판정으로 도전한다(뺏기 없음). `spirits.json`의 `event` 필드와 연결된다. 출현 빈도가 경제에 들어가므로 econ_sim 검증 후에 넣는다.
- W3·W5 권장안: ProximityPrompt는 화면 버튼 역할만 하고, 요청은 항상 기존 Remote 하나로 보낸다. 시설 화면은 HUD Home 버튼과 받침대 Prompt 양쪽에서 열린다.
- W4 접속 시작 위치는 자기 부지.
