## 1. 질문·요구사항

> # 질문
> 빛 정령 방치·수집 Roblox 게임(roblox-game, 1인 개발, 전 세계 대상, 광고비 지출 없음)의 수익 구조를 정리하고 추가 BM을 설계한다.
>
> # 요구사항
> - R1 Roblox 출시·운영 비용과 수익 수수료를 Roblox 공식 문서(create.roblox.com, en.help.roblox.com, devforum 공식 공지 등)로 확인해 표로 정리한다. 항목: 게시·Studio, 게임 서버·트래픽, DataStore(요금·한도), 에셋 업로드(이미지·메시·오디오), 게임패스·개발자 상품 생성 비용, 판매 수수료(개발자 몫), Experience Subscriptions(구독) 조건·몫, Private Servers(비공개 서버) 수익, Premium Payouts, 게임 안 광고 수익(보상형 영상 광고 등)의 조건·연령 제한, DevEx(환율·최소 금액·자격), 세무 양식(비미국 거주자). 각 행에 출처 URL과 확인 내용을 적고, 공식 문서로 확인 못 한 것은 "미확인"으로 표시한다.
> - R2 현재 게임에 정의·결정된 BM을 정리한다: 상품 후보(id·종류·가격), 과금 원칙·금지 범위, 유보·미결 사항. 근거 위치(파일:줄)를 단다.
> - R3 추가 BM 후보를 제안한다. 후보는 (a) 현 원칙 안 (b) 원칙 완화가 필요한 안으로 구분한다. 후보마다: 내용, Roblox 수단(게임패스·개발자 상품·구독·비공개 서버·광고·Premium 등), 출시 시점(MVP/출시 후), Robux 가격대, 경제·공정성 영향(무과금 대비 진행 차이, 기존 시뮬 판정 기준과의 충돌 가능성), 정책 위험(유료 랜덤·PolicyService·연령·확률 공개), 구현 비용(1인 개발 기준).
> - R4 후보의 우선순위와 이유, 피해야 할 BM과 이유를 제시한다.
>
> # 관찰 (사실)
> - 현재 과금 원칙(roblox-game/CLAUDE.md "게임 원칙"): 정령 판매·유료 뽑기·행운 상품·정령 스탯 직접 버프 상품 없음, 외형·편의 중심, 유료 차단 범위 = 포획 투입물·시도 수·확률(기존 과금 해금 단축은 유지). 유료 재료가 랜덤 결과에 쓰이면 간접 유료 랜덤으로 보고 확률 공개·PolicyService 확인이 필요. PvP 약탈 없음, 거래는 MVP 미구현.
> - 상품 후보 데이터: data/products.json(6종). 검증 규칙: tools/econ_sim/econ_sim/validate.py(허용·금지 상품 종류).
> - 게임 본체(Luau)는 MVP1 구현 중이며 상품은 아직 게임에 연결되지 않았다.
>
> # 제약

> - 매출 예측 수치는 내지 않는다(근거 없음). 가격대는 Robux 범위로만.
> - 파일 수정·시뮬 실행 금지. 웹은 공식 문서·정책 확인용 공개 질의만.

## 3. Codex 제안
- 요약: 권장 구조는 무료 진입 + 확정형 외형·편의 판매를 중심으로, 출시 후 조건부 광고·비공개 서버·외형 구독을 붙이는 방식이다. 현재 상품 6종은 모두 placeholder이며 MVP1의 과금 연결은 범위 밖이다. 공식 문서상 게시의 연령별 조건·선택 비용, DataStore 초과 과금, Premium Payouts를 대체한 Creator Rewards가 있어 ‘운영은 무조건 무료’로 정리하면 부정확하다. 이미지·메시 업로드 및 개발자 상품 생성의 명시적 무료 근거, 일부 문서 간 한도 충돌은 미확인으로 남겼다. 가격 제안과 우선순위는 설계 가설이며 매출 예측·실행 승인이 아니다.

## 4. Claude→Codex 문제 제기와 응답

### I1 [높음/사실] 게시·공개 비용 경로(16+ 공개 조건, 전 연령 공개의 1,000 Robux 환급형·50,000 Robux 신속 경로)의 공식 근거

### 결정 대기 (권장안, 결제 기반 착수 = MVP1 S10 뒤에 확정)
1. 광고 보상 외형은 같은 개발자 상품으로 상점에서도 3~10 Robux에 판다. 광고 전용 외형은 만들지 않는다.

3. 외형 선물은 계속 보류한다.
4. 시즌 패스는 시즌마다 새 게임패스로 판다(자동 회수, 매 시즌 사용자가 생성).
5. 보관함 패스는 지역 가격을 유지하고 가격을 동적으로 표시한다.
6. 구독은 로직만 유지한다. 출시 시 전용 트랙은 즉시 지급으로 바꾸거나 시즌 패스로 통합한다.
